# Roadmap

本路线图只记录未来工作的方向，不等同于已承诺的发布计划；任何工作都必须先确认当前运行状态和安全边界。

## 当前阶段

- 维护 Solana 与 BSC 的 Paper/Shadow 基线。
- 保持 BSC Live 为独立、显式授权、可审计的运行路径。
- 继续观察真实数据质量、Quote 覆盖、订单对账和重启恢复，不把 Quote 或测试结果当成成交事实。

## 下一步优先级

1. **运行可靠性**：持续验证主循环、WSS/RPC 健康、SQLite 单一写入、订单 journal、receipt/余额对账和重启恢复。
2. **数据质量**：补齐可验证字段的覆盖率和 stale/unknown 分类；缺失字段保持 NULL/unavailable，不猜测。
3. **策略评估**：积累足够的完整生命周期后，再做描述性分析；不在小样本上自动调参或新增过滤条件。

## 中期方向

- 统一各链和各模式的状态、健康和审计命名，减少旧文档与实际 runner 的漂移。
- 对已验证的 Venue/Provider 做能力矩阵和故障回放，保持未知协议 fail-closed。
- 在不扩大实时主循环负担的前提下，完善数据留存和低优先级清理。

## 暂不计划

- Solana Live、自动签名/广播或 Jupiter 执行接口。
- 为单个 Token 增加硬编码规则。
- 在没有真实覆盖证据时继续堆叠 Provider、Fallback 或复杂评分系统。
- 用 Binance 指示价格替代链上策略价格、可执行报价或真实成交价。

## 完成标准

涉及交易、钱包、执行或状态恢复的改动，必须经过与风险匹配的测试、最小实际验证、SQLite 检查和配置漂移检查；未完成真实链路验证时，状态只能标记为未验证，而不能称为 Live 已验证。
